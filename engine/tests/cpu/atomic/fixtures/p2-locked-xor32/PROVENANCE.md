# Original C11 discard-result atomic XOR consumer

This self-authored header-free C function calls `__c11_atomic_fetch_xor(word, 32u, __ATOMIC_SEQ_CST)` and discards the old value. Its return type is `void`. The source asserts that `unsigned int` is four bytes and contains no inline assembly. [Clang's C11 atomic builtin documentation](https://clang.llvm.org/docs/LanguageExtensions.html#c11-atomic-builtins) describes the source interface. Ring3's finite private-memory evidence does not establish C11 concurrent ordering.

The complete original function loads the pointer from `[ESP+4]`, executes `LOCK XOR DWORD [EAX], 0x20` at offset 4, and naturally returns at offset 8. EAX happens to retain the pointer in this artifact; it is not a C return value. A separate 46-byte guest caller will call this unchanged original twice on one live cell, pause before the first LOCK, load memory after each natural return, and add both observations. The cell starts at `0xA5A55A5A`; the first call produces `0xA5A55A7A`, and the second restores `0xA5A55A5A` with a new write. The caller consumes both values into `0x4B4AB4D4`. A missing operation would yield `0x4B4AB4B4`, so the sum cannot cancel two equal wrong observations. CPU and RAM remain live between calls, with no host reseed. The caller is distinct from the compiler-produced function.

The earlier old-return C11 fetch-or candidate emitted a supported LOCK CMPXCHG32 loop. Later discarded-result OR and AND sources exposed their own original paths. This discarded-result fetch-xor source retains its independently observed compiler output.

The product scope is exact single `F0 83 /6` memory DWORD with a signextended imm8 mask and existing 32-bit effective addresses. The [Intel XOR reference](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2c-manual.pdf) defines full-mask XOR, sign extension, cleared CF/OF and result-derived PF/ZF/SF, with AF undefined. Ring3 reuses its ordinary logical flag policy: retain DF and reserved bit 1 (value `0x2`), compute PF/ZF/SF, and deterministically clear AF with CF/OF.
