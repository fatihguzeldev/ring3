# Original WORD fetch-add consumer

This self-authored, header-free C11 function performs one relaxed atomic fetch-add on an unsigned 16-bit cell and naturally returns its old WORD. The source is retained unchanged. The fixed compiler profile and ordinary COFF extractor come from `../p2-compiled-records/build.py`, pinned to SHA256 `fe426f202b48664a87357c766d39099b9d35b5d8217c2b114696164a0d468258`. The only extractor adaptation substitutes the `ring3_fetch_add` function symbol and its diagnostic spelling for `ring3_reduce`.

Two fresh discovery builds retained the complete original 15-byte function, object and Intel disassembly without editing the produced bytes. The final builder checks the observed whole text and object hashes, one ordinary i386 COFF function, zero timestamp, no relocations or unresolved externals, empty `.data` and `.bss`, and the existing 100-byte `.debug$S` metadata section. It uses the same compiler flags, tool paths and environment as the pinned profile, records exact commands and tool/source/builder hashes, and checks that those inputs remain unchanged. A final formal build will be compared with both discovery outputs; the execution record and equality proof belong to the ignored evidence bank. Routine tests consume the frozen artifacts and do not require a compiler.

The original COFF is 532 bytes, SHA256 `6856790556a30844a4014ce6c89bb59b299fcaff202860e4e994bff09f1d4f27`; the Intel disassembly is 353 bytes, SHA256 `8760da3745efebdc3250ab0a57c502f45ec784fb06d5f8166e86bbf9396ff1e9`. The C ABI defines an unsigned-short return in AX. The separate guest caller explicitly MOVZXs AX before using either returned value.

The planned actual fixture reuses replacement/resident and explicit/entry compilation. Its separate authored caller pushes the pointer and an argument whose high 16 bits are nonzero, calls the complete original, then passes the normalized first old WORD as the second increment without host CPU or RAM reseeding. The first leaf stops naturally after budget 2 at PC 0x2009 before the locked instruction, then resumes with budget 2 through its real RET. The remaining call returns through its own real RET. The fixed input BEEF plus 1234 produces D123 and returns BEEF; the second increment BEEF produces 9012 and returns D123. The guest consumes both old values as BEEFD123. This caller is distinct from the untouched compiler output.

The planned finite controls cover WORD source parents and effective-address aliases, arithmetic flags consumed by later guest instructions, read-before-write faults and repair-only continuation, split-page and top-address rules, source-zero and changed executable writes, ownership/currentness, and nonforwarding malformed helper packets. The unchanged V6 40-byte helper retains the original WORD on success; ordinary read16 remains V2 and DWORD stack read/store remains V1. A source-zero operation still performs a checked write and can invalidate consumed code. Expected execution counts are fixed before execution in the evidence bank and observed counts remain in the result, rather than changing this source-pinned document afterward.

Every generated call is intended to compare the full 4364-byte arena, including a valid distinct dirty 128-byte FP region. Saved compiler milestones and final arenas provide a finite persisted subset. Selected data, stack and executable-code frames provide neighboring-byte evidence; this does not claim all guest RAM was compared or every per-run arena was persisted. Synthetic malformed imports never forward to a real transaction, so their neutral RAM proof does not claim rollback after an arbitrary external commit.
